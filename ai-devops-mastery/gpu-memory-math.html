Step 1: Static Weights Footprint

Formula: Memory = Parameters × Bytes_Per_Weight

For Llama-3-70B in 16-bit (FP16/BF16, 2 bytes):
70 × 10^9 × 2 bytes = 140,000,000,000 bytes ≈ 140 GB.

This memory is completely static and independent of how many users are actively querying the server.

QA-04 • Hardware Profiling
GPU Utilization vs Occupancy vs Memory Bandwidth (The Roofline Model)
Source: Pallavi Ahuja • Track: AI Platform / DevOps • Difficulty: Hard
▼
The Scenario: "Your nvidia-smi shows 100% GPU utilization while serving an LLM, but token throughput is disappointingly low. Your manager asks if buying faster GPUs is the only fix. How do you explain why 100% GPU utilization is deceptive?"
The Deception:

nvidia-smi's utilization metric only measures the percentage of time that any kernel was executing on the GPU. If a single warp is fetching memory from DRAM while the other 128 SMs sit completely idle, nvidia-smi still reports 100% Utilization!

  • Decode Phase is Memory-Bound: Each generated token must load 140GB of weights from HBM to register files. The GPU is memory-bandwidth bound ($O(1)$ arithmetic intensity).
  • Nsight Profiling (nsys): Profile DRAM throughput vs Tensor Core active cycles. If DRAM throughput is at 95% while SM compute is at 15%, you cannot fix it with faster clocks—you need Continuous Batching, Quantization (FP8/AWQ), or PagedAttention.

QA-01 • The STAR Framework
The "Tell Me About a 2 AM Production Failure" Incident
Source: Bharath Reddy (40 LPA Loop) • Track: AI DevOps / SRE • Difficulty: Hard
▼
STAR War Story Delivery:
  • Situation: At 2:15 AM, p99 latency on our customer service AI agent spiked from 800ms to 48 seconds, triggering PagerDuty alerts across the platform team.
  • Task: Identify the root cause, restore service without dropping customer chats, and eliminate the vulnerability permanently.
  • Action: Low-level tracing revealed a downstream CRM API was returning HTTP 429 HTML rate-limit error pages. The agent interpreted the HTML body as new instructions and entered an unbounded reflection loop. We applied emergency circuit breakers, capped max_iterations = 4, and enforced exponential backoff with full jitter.
  • Result: P99 latency recovered to 650ms. Incident post-mortem introduced automated CI/CD chaos tests, saving estimated $45k/month in runaway token loops.
QA-09 • Network Race Condition
Intermittent 502 Bad Gateway Under AI Inference Load
Source: Rishabh Tripathi • Track: DevOps / Platform • Difficulty: Medium-Hard
▼
The Mystery: 1.5% of requests fail with 502 Bad Gateway, but backend CPU is low and pods are not restarting.
The TCP Keepalive Race Condition:

When the upstream reverse proxy (Nginx / ALB) has a keepalive timeout longer than or equal to the backend server (FastAPI/Uvicorn), the backend can send a TCP FIN at the exact microsecond the proxy forwards a new request, resulting in an immediate TCP RST.

The Golden Rule: Backend keepalive timeout must ALWAYS be strictly greater than proxy timeout: 
# Nginx Ingress: keepalive_timeout 65s;
# Uvicorn:       uvicorn.run(..., timeout_keep_alive=75) # 75s > 65s!

Q1. Agent vs reliable agent

Interviewer asks: Refund tool returns {amount:null}. Does workflow recover? Retries/timeouts? Walk me through.
Tests: survive 3am prod, not demo.
Priya story: Demo froze on Stripe 500. No answer. That night she learned 5 shields. Next time she drew diagram below and got hired.
30-sec answer (say aloud): 10s timeout, 3 retries 2/4/8s, Pydantic validate, fallback cache/human, checkpoint resume, LangSmith trace.

Picture: without vs with (study 30s)

Before: No timeout hangs. Null crashes math. One 500 kills order. Restart double-charges. No trace = cannot explain.
After: Timeout stops hang. Pydantic rejects bad shape. Retries absorb flakes. Cache keeps user going. Checkpoint resumes. Trace proves Try1 fail to Try3 win.

Step-by-step: fix in this order (why each)

1
Timeout 10s: stops infinite hang. Ask: if API never replies, what saves you? Timeout.
2
Validate (Pydantic): Customer(balance:float) rejects null immediately, before bad math spreads.
3
Retry 3x: only for network/5xx/429 (transient). Never retry validation errors.
4
Fallback: cached balance or human. User sees help, not crash.
5
Checkpoint+trace: save progress, resume; record attempts to prove recovery.
READ CODE LINE BY LINE:
@retry(...) = auto retry flakes, wait longer each time
timeout=10 = never hang over 10s
Customer(**json) = reject wrong shape now
# checkpointer = save + resume after crash
from tenacity import retry, stop_after_attempt, wait_exponential
from pydantic import BaseModel
class Customer(BaseModel): id: str; balance: float
@retry(stop=stop_after_attempt(3), wait=wait_exponential(2,2,10))
def get_customer(cid: str):
 import requests
 r = requests.get("https://api.example.com/c/"+cid, timeout=10)
 r.raise_for_status()
 return Customer(**r.json())

Q2. RAG vs evaluated RAG

Interviewer asks: You wired docs to vector DB. How do you measure retrieval quality? 3 good queries is not proof. Convince me prod works.
Priya story: Her bank bot answered 3 demo questions perfectly, failed on question 4 in interview ("What is overdraft fee for students?") — retrieved wrong chunk. She learned to test like an examiner: 200 questions, two scorecards.
30-sec answer: Golden 200 QA set. Librarian score (Recall@k, MRR) + Writer score (Faithfulness) separately via RAGAS + Phoenix. CI gate: ship only if faithfulness over 0.85.

Picture: Librarian + Writer (two jobs, two scores)

Before: 3 manual queries looked good. Prod: wrong chunk + hallucinated fee = angry customer + compliance risk.
After: 200 QA golden set. Bank recall 0.68 to 0.86 after chunk fix. Hospital blocks answer if faith below 0.92 ("not in docs"). E-com auto re-embeds on drift.
from ragas import evaluate
from ragas.metrics import faithfulness, context_precision, context_recall
print(evaluate(dataset, metrics=[faithfulness, context_precision, context_recall]))
# rule: ship only if faithfulness over 0.85 and recall over 0.8

Q3. Tools vs orchestrated workflows

Interviewer asks: Agent must: get customer, charge, reserve stock, update CRM. Stock API fails AFTER charge. Customer charged with no item? Show your design.
Priya story: She charged a test card $120, then inventory failed. Money stuck. Interviewer: "Refund?" She had none. She learned saga: every success gets an undo.
30-sec answer: State machine, validate each step, saga compensation (refund if later fails), idempotency key, human approval for risky acts, resume.

Picture: happy path vs saga rescue

state={"pay":None}
try: state["pay"]=charge(cust); update_crm(state)
except Exception as e:
 if state["pay"]: refund(state["pay"]); notify_ops(e); raise
# every success has an undo. No stuck money.
